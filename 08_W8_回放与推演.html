Sequencer：本周唯一的新技术

在虚幻引擎中通过蓝图播放过场动画 ★ 本周首推
Epic 官方已实测·中文正文（全中文可照抄）必学
→ 打开（中文）
为什么这周看它：这是你这一周最该用的一篇——全中文、纯蓝图、18 个编号步骤可以照抄，而且它恰好覆盖了你要的全部要点：
① 添加关卡序列（Add Level Sequence）、给灯光强度打关键帧、添加相机并打关键帧；
② 在关卡蓝图里：Create Reference to Level Sequence → Play（Sequence Player）；
③ 最容易踩的坑：Set Playback Position 要设为 0，否则序列只播一次、二次触发无效；
④ When Finished 设为 Keep State：让序列改动的结果在播完后保留（例如「剖切动画播完保持剖开状态」）；
⑤ Go to End and Stop：做「跳过动画但保留结果」。
⚠️ 需要注意的迁移工作：教程绑的是触发器重叠事件，你要换成 UMG 按钮点击或构件点选触发，逻辑结构不变。

导出能力（合同第 15 条）

ECharts 导出：PNG 用 getDataURL，PDF 走浏览器打印

→ 使用手册（中文）
为什么这周看：合同第 15 条要求「监测数据导出 Excel/CSV，图表导出 PNG/PDF」。做法建议：
① CSV：前端拼字符串 + Blob 下载，最简单可靠；

③ PNG：ECharts 的 getDataURL() 直接拿；

提醒：导出功能很容易被忽略，但它是必查项——验收时会现场点，务必四个格式都实测一遍。

逐日任务（D1–D6）

D1（3–4 h）历史回放：数据侧（Web）

  1. 回放的数据接口：给定「测点 + 时间范围」→ 返回按时间排序的序列。要点：
    • 降采样：1 年数据不可能一次返回。按时间跨度自动选粒度（1 h 用原始点、7 d 用分钟均值、1 月用小时均值）
    • 支持多测点同时回放（演示时通常要整个分区一起动）
  2. 回放控制条：播放/暂停/进度拖动/倍速（1×、2×、4×、8×）/跳转指定时间。
  3. 回放时曲线要跟着走（播放头位置指示），而不是整条曲线都在。
  • 能选任意时段并回放（含 1 h / 24 h / 7 d 至少三档）
  • 有进度条、暂停、倍速
  • 大数据量下不卡

D2（4 h）历史回放驱动三维着色（合同第 15 + 6 条）

  1. 回放数据流：Web 按回放进度批量推送数据帧到 MQTT（不要一条条发，按帧打包，例如每 200 ms 一帧包含该时刻所有测点值）。
  2. UE5 侧：订阅回放主题 → 解析帧 → 更新构件着色。与实时模式共用同一套着色逻辑（只是数据源不同）——这是设计上的关键，不要写两套。
  3. 模式切换：界面上明确「实时 / 回放」状态，切回实时要能立刻恢复。
  4. 演示脚本：设计一段 2 分钟的回放演示（例如加载试验全过程），录成视频。
  • 回放能驱动三维构件颜色变化
  • 实时/回放可切换，切换不出错
  • 有 2 分钟演示视频

D3（3 h）导出四项全通（合同第 15 条）

  1. 监测数据导出 Excel：选测点 + 时段 → 出 .xlsx，含列头、时间列、数值列、单位。
  2. 导出 CSV：同上，适合大数据量。
  3. 图表导出 PNG：ECharts getDataURL()，注意背景色（不然导出是透明的，投影会难看）。
  4. 图表导出 PDF：用打印样式 + window.print()，或前端 PDF 库。验证打印分页是否正常。
  5. 把四个导出文件都存一份作为证据：Docs\evidence\27条验收\C15_导出_*.{xlsx,csv,png,pdf}。
  • 四种导出格式各成功一次且有文件留证
  • 导出的 Excel 能被 Excel/WPS 正常打开，无乱码
  • PNG 背景正常、PDF 分页正常

D4（4 h）吊装推演：Sequencer 动画（增强项）

先明确验收口径 你已确认推演只需「看着像的过程回放」，不需要真实的索力-位移耦合物理仿真。这是明智的降级—— 真做物理耦合，单人 90 天不可能完成。
  1. 场景准备：确认孪生场景里有吊装推演所需的元素（两端塔架、缆索、节段）。若无分节段几何，用简化块体代表 44 个节段（外观像即可）。
  2. 建关卡序列：
    • 节段吊装：从地面升到设计位置（位置关键帧 + 缓入缓出）
    • 两岸对称悬臂拼装：左侧节段 → 右侧节段 → 交替推进（对称是桥梁施工的关键特征，演示时要体现出来）
    • 拱顶合龙段：最后一段合龙（可加高亮强调）
    • 相机：几个预设机位切换（俯瞰 → 侧面 → 拱顶特写）
  3. 联动数值展示：在动画过程中显示「塔顶位移 / 扣索索力 / 节段标高」的数值变化（可用 UMG 数字滚动，或用已有的测点数据）。 不要求数值物理正确，但要有来源说明（例如「示意值」）。
  4. 蓝图控制：按 D1 资料区的要点接好（注意 Set Playback Position = 0 与 Keep State 两个坑）。
  5. 导出视频：用 Sequencer 的渲染影片功能或录屏，存一段 60–90 秒的推演视频。
  • 推演动画可播放、可重播（第二次仍能播）
  • 体现两岸对称拼装与拱顶合龙
  • 数值面板随动画变化
  • 有 60–90 秒视频

D5（3 h）性能复核 + 稳定性

  1. 回放时的性能：回放比实时更密集（批量推送），用 stat unit 与 stat gpu 确认帧率仍在达标范围。
  2. 长时间运行测试：让系统连续跑 2 小时（含实时数据 + 反复回放），观察是否有内存增长、连接掉线、帧率衰减。
    • 显存泄漏要特别留意（有社区报告提到 Nanite + 光追下显存持续增长；你不用光追可规避，但仍要盯）
  3. 记录测试结果与发现的问题。
  • 回放时性能达标
  • 2 小时连续运行无崩溃、无显著内存增长
  • 有问题清单与处理结论

D6（3 h）第 2 次全表普查 + 砍补决策（关键节点）

今天必须做出取舍决策 只剩 4 周。今天要把「哪些条款确定能过、哪些有风险、哪些要降级」写清楚，并同步给项目负责人。 提前沟通是项目管理，拖到验收是事故。
  1. 逐条过 27 条，形成四类清单：已达标 / 本周可补 / 有风险 / 需降级。
  2. 本周结束时，未动的条款应该只剩 第 9、10 条（轻量化）、第 22–27 条（系统设置/RBAC/日志），以及 W9–W10 的像素流相关能力。
  3. 针对「有风险」条款做出决策：
    • 第 9、10 条（轻量化压缩率 ≥70%、解析 ≤60 s）——这条依赖模型管线，若 rvt 路线难压缩，需评估 IFC 路线或第三方轻量化工具
    • 像素流并发——若甲方要求独立视角，需立即启动多实例方案评估
  4. 把决策清单发出去并留存记录。
