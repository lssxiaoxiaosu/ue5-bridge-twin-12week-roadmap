Web 融合：把三维画面嵌进业务平台

本周目标：定制像素流播放器页面；把三维画面嵌入 Web 业务后台，实现「一个页面里同时有看板和三维」；打通 Web ↔ UE5 双向指令通道（点测点 → 相机飞过去）。

双向指令通道：本质是 W3 定好的 MQTT 主题

EMQX 官方中文文档（主题与订阅复用于指令通道）
EMQX 官方已实测·中文正文复用
→ 打开（中文）
为什么这周再看：本周的「Web ↔ UE5 双向通道」不需要新协议——就是 W3 已定好的两个主题：
bridge/<桥名>/cmd/ue5（Web → UE5 指令）　与　bridge/<桥名>/state/ue5（UE5 → Web 状态回报）
为什么用 MQTT 而不是让 Web 直接调 UE5 的 HTTP 接口：UE5 蓝图主动发 HTTP 请求容易，但被动接收 HTTP 请求需要额外插件或服务； 而 MQTT 两边都是订阅模式，对称、简单、可复用同一条链路。这是 W3 就把主题定下来的价值兑现。

逐日任务（D1–D6）

D1（3–4 h）播放器页面定制（去掉默认 UI）

  1. 定位要改的文件：在 PixelStreamingInfrastructure 的 Frontend/ 下找到播放器页面与其样式 / 脚本。
    一个官方明确提醒过的坑 修改要改原始仓库位置的文件；如果你改的是打包输出目录里的副本，下次打包会被覆盖。
  2. 去掉默认 UI：隐藏播放按钮层、设置齿轮、统计信息面板、全屏控件。
    • 目标：页面加载后自动播放，界面上只保留你自己要的元素
    • 需要保留「点击页面后才能播放」的浏览器策略兼容（多数浏览器要求用户交互后才能播放媒体）
  3. 做一层自己的 loading 提示：等待连接到 streamer 期间要有明确反馈（否则用户以为坏了）。
  4. 验证：直接打开定制后的页面，能自动出画面、无默认 UI。
  • 默认 UI 已去掉
  • 页面加载后能自动播放（含必要的交互兼容）
  • 有加载中提示

D2（3–4 h）嵌入 Web 后台（iframe 方案）

  1. 布局设计：一个页面里同时有看板与三维。建议：
    • 左侧/顶部：测点列表、指标看板、告警列表
    • 右侧/主区：UE5 三维画面（iframe 嵌入）
    • 底部：曲线与时间轴
    把你现有原型的界面改造成这个布局——它的三维区原本是 Three.js 画布，现在换成 iframe。
  2. iframe 嵌入：注意三点
    • 跨端口/跨域时的 allow 属性（全屏、自动播放等）
    • 性能：iframe 里的视频流会持续占用带宽与解码资源
    • 提供一个「隐藏三维」开关——不演示时可关闭以省资源
  3. 统一视觉：让三维画面与 Web 界面的风格协调（深色科技风），不要让用户感觉是两个系统拼起来的。
  4. 验证：一个 URL 打开后，看板与三维同屏显示且都能操作。
  • 单个页面同时显示看板与三维
  • 布局在投影分辨率下可读
  • 有隐藏三维的开关

D3（4 h）Web → UE5：点测点，相机飞过去

  1. 定义指令消息格式（写进文档，两边照此实现）： 
    主题: bridge/<桥名>/cmd/ue5
报文: {"cmd":"focus","elementId":"SG-01-05","camera":"preset|auto","ts":1758700000}
其他指令示例: {"cmd":"view","preset":"overview"}  {"cmd":"layer","category":"吊杆","visible":false}
              {"cmd":"playback","action":"play","elementId":"SG-01-05","from":...,"to":...}
  2. Web 侧发送：点测点/告警/图层开关 → 通过 MQTT（浏览器端可用 MQTT over WebSocket）发指令。
  3. UE5 侧接收：订阅该主题 → 解析 cmd → 分发到对应处理（相机、图层、回放）。
    • 复用 W4 的 Set View Target with Blend 做平滑飞行
    • 复用 W2 的构件高亮与属性面板
  4. 处理异常：构件编号不存在时不要静默失败，要回一条错误状态。
  • Web 点测点，UE5 相机飞到对应构件并高亮
  • 图层显隐也能从 Web 控制
  • 构件不存在时有错误反馈

D4（3 h）UE5 → Web：状态回报

  1. 定义状态消息： 
    主题: bridge/<桥名>/state/ue5
报文: {"state":"ready|busy|error","selected":"SG-01-05","fps":32,"visibleElements":1071,"ts":...}
  2. UE5 侧发送：在这些时机发状态——
    • 场景就绪（加载完成）→ 通知 Web 可以隐藏 loading
    • 用户在三维里点选构件 → Web 侧看板/曲线自动切到该测点（这就是反向定位，W7 已做过一部分）
    • 周期性上报 fps 与可见构件数（这同时是合同第 5 条的性能自证，一举两得）
  3. Web 侧订阅：根据状态更新界面（显示 fps 角标、同步选中项）。
  4. 把 fps 显示在 Web 界面上——验收时甲方问「帧率多少」，你指着屏幕就能答，比翻控制台有说服力。
  • UE5 就绪状态能通知 Web
  • 三维里点构件，Web 看板自动切换
  • Web 界面显示实时 fps 与可见构件数

D5（3–4 h）输入权限控制（对应「主持人控制」）

  1. 确认你要的形态：按 W9 的确认结果——
    • 同视角 + 主持人控制（推荐）：只有主持人能操作，其他人纯观看
    • 独立视角：需要多实例，见 W9 的风险说明
  2. 实现主持人控制：
    • 在播放器页面侧限制非主持人的输入（官方播放器页面提供输入控制能力）
    • 或更简单：只给主持人一个「可操作」的 URL 参数，其他人打开的是只读版本
  3. 验证：用两个浏览器分别以主持人与观众身份打开，确认观众操作无效。
  4. 把这条写进方案与操作手册——它是「2–4 人同时使用」的落地方式，验收时会问。
  • 存在「可操作」与「仅观看」两种接入方式
  • 已验证观众无法干扰主持人操作
  • 已写入文档

D6（3 h）整合演练 + 里程碑判定

  1. 完整走一遍典型使用流程（写下来当操作手册的雏形）：
    1. 主持人打开平台页面 → 三维自动加载
    2. 查看实时看板 → 点一个测点 → 三维飞到该构件
    3. 切换图层显隐 → 切换预设视角
    4. 触发一次告警 → 点告警定位到构件
    5. 切到历史回放 → 三维随回放变化
    6. 观众从另一台设备同时观看
  2. 录一段 5–8 分钟的完整演示视频——这是 W12 验收演练的底稿。
  3. 更新验收自测表与证据包。
  • 完整流程一次走通，无卡顿无报错
  • 5–8 分钟演示视频已存证
