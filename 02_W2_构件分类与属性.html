WEEK 02 ／ 12

构件分类与属性：把 5000+ 个构件变成 8 类可识别对象

本周目标：把「一堆导入进来的构件」变成「8 类可识别、可拾取、可看属性的构件」——这是合同第 2、3、4 条的地基，也是所有数据联动的挂接点。

建议工时 22–26 h 学习 : 实做 ≈ 40 : 60 对应条款 第 2、3、4 条（8 类覆盖、一致性、交互） 前置 W1 检查点必须全过
本周的认知准备：蓝图只需要学 6 个东西 不要打开「UE5 蓝图全套教程」。本周只会用到下面 6 个概念，遇到就去查这 6 个关键词，别的先不看：
概念一句话理解本周用在哪
变量存东西的盒子，有类型存「当前选中的构件」「分类结果」
事件「什么时候做什么」BeginPlay 初始化；输入触发拾取
函数 / 宏把一串节点打包，可重复调用把「分类构件」写成函数
结构体 Struct自定义的「一条记录」构件信息的数据格式（本周核心）
数据表 DataTable一堆结构体组成的表格，可从 CSV 导入把分类结果变成表（本周核心）
Actor 与 ComponentActor 是「物体」，Component 是它身上的零件拾取要抓 Component；属性挂在 Component 上
这 6 个概念覆盖 W2–W4 的全部需求。要做着色时再学动态材质实例，要接数据时再学 MQTT 与 JSON。

逐日任务（D1–D6）

D1（3 h）把构件清单「导出来」——分类问题的真正解法

  1. 先看清楚你的数据（30 min）：World Outliner 里观察构件命名规律（Datasmith 导入后 Actor 名通常保留 Revit 族名/类型名）；打开一个构件的 Details → Datasmith User Data，把所有可用的 key 名抄下来。
  2. 量化规模（30 min）：记录总构件数；并对照合同记录 8 类的期望数量：
    类别合同要求数量你实测的数量
    主拱肋节段单侧 22 × 2 侧 + 合龙段
    吊杆32 对（64 根）
    横联钢管按图
    腹杆按图
    桥面系钢格子梁按图
    两端塔架2
    缆索锚索 20 / 扣索 20 / 吊索 4
    基础2
  3. 导出构件清单到 CSV（1.5 h，本日核心）：
    • 路径 A（推荐，零编程）：用 UE 的 Tools → Execute Python Script（需先启用 Python Editor Script Plugin）或 Editor Utility Widget（EUW，纯蓝图的可视化编辑器工具），遍历所有 StaticMeshActor，导出 Actor 名 / 标签 / 各元数据 key / 面片数 / 包围盒尺寸
    • 路径 B（兜底）：在 Datasmith 导出设置里勾选需要的元数据，再到 Revit 侧直接出构件明细表
    • 产物：D:\UE\Docs\构件清单.csv
  4. 在表格里做分类（30 min，Excel/WPS 即可）：用筛选/公式把每个构件归到 8 类之一，无法归类的先归「其他」但「其他」必须尽量小；加 类别 与 构件编号（按四码合一规则命名）。
    自检问题：这条规则能不能用「名字包含某某关键词」表达？能的就写成规则；不能的说明元数据没带出来，回去补导出设置。
  • 构件清单.csv 已生成，行数 ≈ 构件总数
  • 8 类 + 「其他」的分类列已填满，「其他」占比能说出结论
  • devlog 写下：分类依据字段 = ______

D2（3 h）DataTable + 结构体（本周第一个真蓝图）

  1. 建结构体：Content Browser → 右键 → Blueprints → Structure，命名 S_构件信息，字段： 
    构件编号(String) / 构件名称(String) / 类别(Enum) / 材质(String)
规格(String) / 节段序号(Int) / 面片数(Int) / 中心坐标(Vector) / 备注(String)
  2. 建枚举：Blueprints → Enumeration，命名 E_构件类别，8 个值：主拱肋节段 / 吊杆 / 横联钢管 / 腹杆 / 桥面系 / 塔架 / 缆索 / 基础（可加 其他）。
  3. 导 CSV 成 DataTable：把 CSV 整理成「首行字段名 + 与结构体字段一一对应」；右键 → Miscellaneous → Data Table，行结构选 S_构件信息，再 Reimport 导入 CSV。
    三个高频坑 CSV 必须 UTF-8（最好不带 BOM）　｜　枚举列要写枚举项名而不是中文显示名　｜　字段名不能有空格， 并且要让 RowName ＝ 构件名或构件编号（后面查表最方便）。
  4. 写出第一个蓝图函数：Get 构件信息 by 名称：输入 Actor 名 → Get Data Table Row → 输出结构体，用 Print String 验证。
  • DataTable 导入成功，行数对得上（不是 0 行，也不是只有 1 行）
  • 蓝图能查出任意一个构件的信息并打印出来
  • devlog 记录：DataTable 行数 = ______

D3（3–4 h）构件自动分类 + 分层显隐

  1. 写「批量分类」蓝图：遍历关卡内所有 StaticMeshActor → 按 D1 的规则判定类别 → 写入。
    • 写入方式两个都做（成本很低）：Actor Tags（如 Cat_主拱肋节段，显隐与筛选最方便）+ 回填 DataTable
    • 用到的节点：Get All Actors Of Class、For Each Loop、Get Datasmith User Data Value for Key、Actor Set Tags
  2. 验证分类正确性（本日价值所在）：写一个临时函数按类别统计数量并打印，与 D1 的期望数量对照；对不上的去看是哪些被误分，修正规则。
    必须在今天做 分类错了，后面 130 个测点全会挂到错误构件上。如果与合同数量差很多，当天就在 devlog 记下结论—— 这可能是「原型桥几何 vs 缩尺实体不一致」的第一个实证，需要反馈给甲方。
  3. 做分层显隐（合同第 4 条的一项）：用 8 个类别做 8 个开关（UMG CheckBox 或先用按键测试），按 Tag 筛选 → Set Actor Hidden In Game。
  • 8 类统计数量与合同/图纸基本吻合（偏差有解释）
  • 8 个类别开关能各自显隐且互不干扰
  • Actor Tags 里能看到 Cat_* 标签

D4（4 h）构件级拾取 + 高亮（合同第 4 条核心）

  1. 实现拾取：首选节点 Get Player Controller → Get Hit Result Under Cursor By Channel（比手动 LineTrace 少一半节点）。
  2. 性能红线（务必遵守）：绝不要做「对每个三角形求交」的拾取。
    • 若构件没有碰撞体 → StaticMesh 的 Collision 设置里开 Use Simple Collision As Complex 或 Add Box Simplified Collision
    • 反过来：别给构件开 Complex Collision，5000+ 构件会拖垮拾取
    • 新建一个自定义碰撞通道（如 TwinPick），只让构件响应它，避免打到地形/灯光
    你已经在别处踩过这个坑 你现有 Web 原型的 v1.1 修复记录里就有：悬停拾取对全模型做三角形级射线求交导致页面卡死，后改为包围盒拾取 + 90 ms 节流。 UE 里同样会踩——直接按「简单碰撞 + 节流」开工，加 0.08–0.1 s 节流（Timer 或 Set Timer by Event）。
  3. 高亮反馈：推荐用 自定义深度（Custom Depth / Stencil）——成本极低、效果清晰，材质里加后处理描边即可。备选：替换材质（简单但丢原观感）、描边后处理（最漂亮，W11 有余力再升级）。
  • 鼠标移上去能选中构件，并打印出它的名字与类别
  • 高亮效果可见
  • 拾取时 stat unit 的 Game 线程时间不飙升（<5 ms）

D5（3–4 h）UMG 属性面板（合同第 4 条「查看属性」）

  1. 学 UMG 最小集：Widget Blueprint、Canvas Panel、Text Block、Vertical Box、Bind、Create Widget / Add to Viewport。
  2. 做属性面板：拾取到构件后在屏幕一侧弹出，显示合同明确要求的 4 项：编号、材质、规格、实时数据（实时数据先显示「待接入」占位）；补充显示类别、节段序号、面片数、中心坐标以增加可信度。
    数据来源：D2 的 DataTable 查表；查不到再回落到 Get Datasmith User Data Value for Key。
  3. 面板交互：未选中隐藏 / 选中出现 / 点空白取消；加一个「定位」按钮把相机对准该构件——这一条会复用为 W5 的「告警点击定位」，现在做一次省两次工。
  4. 把「实时数据」留成参数：面板上放一个绑定到变量 当前测点值 的字段，接真数据时只改数据源、不改界面。
  • 点任意构件，面板显示其编号/材质/规格且与元数据一致
  • 面板有「实时数据」占位字段
  • 「定位」按钮能把相机对准构件

D6（3 h）预设视角 + 相机控制 + 本周收尾

  1. 第一人称漫游：用 DefaultPawn（Play → DefaultPawn + F 键聚焦）或简单的 SpringArm + Camera 蓝图。
  2. 6 个预设视角：摆 6 个 Camera Actor（全景 / 正视 / 侧视 / 拱顶 / 桥面 / 吊装视角）并改名，用数组存起来，按数字键或按钮切换，用 Set View Target with Blend 做平滑插值（比硬切专业得多，成本几乎为零）。
  3. 做成演示快捷键：1–6 切视角、P 开属性面板、L 显隐图层面板——验收演示时你不想翻菜单找按钮。
  4. 更新验收自测表，把本周完成的条款（第 2、4 条大部分）勾上并补证据。
