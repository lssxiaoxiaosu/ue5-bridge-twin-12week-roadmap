一、先读这一页：三个定调

定调一：UE5 只做孪生层，19 条业务后台交给 Web

合同技术要求共 27 条。其中属于「三维孪生」的约 8 条，属于「业务后台」的约 19 条。 在 UE5 里做报表、RBAC 三级授权、日志审计、设备台账，成本是 Web 的 5–10 倍，且单人 90 天做不完两条线。

能力域承担者依据
三维孪生、构件级拾取、剖切/测量/漫游、四档着色、像素流UE5合同 27 条中的三维类条款
看板、历史回放、报表统计、告警管理、设备台账、RBAC、日志审计、BIM 上传与轻量化流程Web（升级现有 Three.js + ECharts 原型）合同 27 条中的业务类条款

浏览器里看到的形态是：Web 后台框架 + 内嵌的 UE5 像素流画布拼在一个页面里，而不是「UE5 里做了一个平台」。

定调二：几何基准用原型桥 BIM 等比缩放（须甲方书面确认）

孪生对象＝平南三桥 BIM 按 1:100 等比缩放。但验收对象是缩尺试验模型（跨 6 m、φ14 mm）， 且缩尺模型对壁厚（2–4 mm）、横联（φ10）、腹杆（φ8）做了非等比妥协，两者并非逐构件严格相似。

处置：书面确认口径 —— 孪生几何＝原型桥等比缩放，一致性以「四码合一编码对应 + 关键尺寸核对表」为准， 不以逐构件几何比对作为验收方式。缩尺模型到货后再做一次实测回填。

定调三：全程 Blueprint（蓝图），不碰 C++

路径：Revit 导出 .udatasmith → Datasmith 导入 UE5 → 纯蓝图开发 → Pixel Streaming 推流。 本路线全部技术点均可用蓝图实现，无需 Visual Studio（可省下 2–3 天环境折腾与大量编译报错）。

七、验收口径与待确认事项

合同验收条款原文（这是排程的硬约束） 「货物验收时由采购人对照采购文件的《技术参数及性能（配置）要求》进行全面核对检验… 如不符合采购文件要求或提供虚假承诺的、虚假检测报告等任何虚假材料的，采购人有权拒绝验收并认定成交供应商违约。」

因此：开发顺序＝27 条逐条落地，亮点功能（吊装推演等）放在条款全部达标之后；每条都要能当场演示 + 能出证据。

#待确认事项为什么必须先确认
1像素流并发口径：2–4 人是「同一视角 + 主持人控制」还是「各自独立漫游」？后者需一实例一流；旧 matchmaker 已于 5.5 弃用。可把 W9–W10 从两天变成两周

3几何一致性口径：是否接受「原型桥等比缩放 + 编码对应 + 关键尺寸核对」？合同写「几何偏差 ≤5%」，而缩尺实体验收前才到货
