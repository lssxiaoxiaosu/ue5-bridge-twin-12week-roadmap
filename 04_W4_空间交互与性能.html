性能与渲染：本周同时要吃透的两块

Nanite 虚拟化几何体
Epic 官方已实测·中文正文必学
→ 打开（中文）
为什么这周看：你的桥梁模型面片量很大，Nanite 是「不让面片数变成帧率瓶颈」的核心手段。重点看：哪些条件会禁用 Nanite、显存开销、以及它对 Instanced Static Mesh 的限制。合同第 5 条「面片 ≤200 万时 ≥30 fps」的达成，很大程度取决于这里。
Lumen 性能指南
Epic 官方已实测·中文正文必学
→ 打开（中文）
为什么这周看：Lumen 是笔记本显卡上最大的帧率杀手。这页给了 30/60 fps 的预算口径与成本构成，是判断「要不要关掉 Lumen」的依据。本项目的策略是默认关闭 Lumen、用烘焙静态光照。
Stat 命令
Epic 官方已实测·中文正文必学（本周天天用）
→ 打开（中文）
为什么这周看：你需要 stat fps、stat unit（分辨是 Game / Draw / GPU 哪个线程卡）、stat gpu、stat rhi、stat initviews。性能排查的全部起点就在这一页，建议打印出来贴在显示器边。
可视性与遮挡剔除
Epic 官方已实测·中文正文本周进阶用
→ 打开（中文）
为什么这周看：stat gpu 显示 GPU 吃不消时，问题往往出在「有多少东西被送进渲染」。这页提供了可直接用的命令： stat initviews（看剔除开销与 Processed Primitives）、r.VisualizeOccludedPrimitives 1（绿框标出被遮挡物体）、 FreezeRendering（冻结渲染后自由走动查遮挡）。
两个实操提醒：遮挡剔除在线框模式下禁用；stat 应在 PIE 或 Standalone 下测，不要在编辑器视口测。
⚠️ 诚实说明：这页通篇不提 Nanite 与 Lumen，所以它不是「取舍指南」，只是「帧率为什么低」的第一性原理。
时序超分辨率（TSR）
Epic 官方已实测·中文正文选学
→ 打开（中文）
为什么这周看：TSR 是「用较低内部分辨率换帧率」的官方手段，与 r.ScreenPercentage 配合， 是你在笔记本上守住 30 fps 的重要旋钮。
⚠️ 提醒：网上流传的「TSR FAQ」页已不存在（本文档实测未找到），请以这页技术总览为准，不要引用失效链接。
虚拟阴影贴图（VSM）
Epic 官方已实测·中文正文选学
→ 打开（中文）
为什么这周看：官方明确 VSM 是「为 Nanite 设计的」。缓存失效（WPO / 骨骼动画 / 移动光源）是主要开销来源——你的桥梁是静态物体，只要不滥用移动光源，VSM 可以保留。这页帮你判断是否值得留。

两点测距：技术要点清单（无已核实中文教程）
无已核实中文教程必做
技术要点（不是引述，是给你自己动手的清单）：
① 用拾取节点（W2 已会）取两个点的世界坐标；
② 用向量长度节点算距离；

逐日任务（D1–D6）

D1（3–4 h）剖切：材质遮罩路线

  1. 在材质里做「平面裁剪」：用 世界坐标（World Position） 与一个 平面参数比较，把一侧像素丢弃或设为透明。
  2. 把平面位置做成材质参数（标量或向量），这是能用蓝图实时控制的前提。
  3. 蓝图侧：创建一个 材质实例（MID），把参数暴露出来；做一个 UMG 滑块（Slider）驱动它。
    如果这里做不动 说明你还没掌握动态材质实例——提前跳到 W5 的「实例化材质」官方页学完再回来。这两周的知识本来就是连着的。
  4. 把剖切做成可开关（开启时裁剪，关闭时恢复原材质）。
  • 拖动滑块能把桥「剖开」，且剖切面位置连续可调
  • 可一键关闭剖切恢复原状
  • 剖切时帧率没有明显下降

D2（3 h）两点测距

  1. 按资料区的 5 个技术要点实现：取点 → 算距离 → 画线 → 显示 → 处理三个交互细节。
  2. 单位换算：显示时把 UE 单位（cm）换算为原型尺寸（×100），并在界面上标明量纲（如「原型尺寸 15.5 m」）。
  3. 让测量可「清除重测」（验收时一定会反复演示）。
  • 点两个点能画出连线并显示距离
  • 第一个点不显示距离、第二点后锁定、可清除重测
  • 数值带正确量纲与单位标注

D3（2–3 h）图层显隐完善 + 第一人称漫游

  1. 图层显隐升级：W2 做的 8 类开关，本周做成正式的 UMG 面板（8 个 CheckBox 带类别名与数量），并支持「全选/全不选」。
  2. 第一人称漫游：确保能自由飞行/行走查看，且不会掉出场景；加一个「回到全景」快捷键。
  3. 把漫游与预设视角做成互斥的两种模式（切换时有提示），避免验收现场误操作。
  • 8 类图层开关面板可用，带数量显示
  • 漫游流畅，有「回到全景」
  • 漫游与预设视角切换正常

D4（4 h）性能专项：守住「面片 ≤200 万时 ≥30 fps」

这是合同硬指标，必须本周出实测数据 验收时要在「面片 ≤200 万」的档位上测帧率，不是在精细档上测。请做一个一键切换的「验收档」，避免现场手忙脚乱。
  1. 先测再调：用 stat fps + stat unit 判断瓶颈在哪个线程：
    • Game 线程高 → 蓝图逻辑太重（For Each 遍历、每帧拾取），加节流/改事件驱动
    • Draw 线程高 → 绘制调用太多（构件数太多、没合并），用 stat initviews 看 Processed Primitives
    • GPU 高 → 用 stat gpu 找最贵项（通常 Lumen / 虚拟阴影 / TSR）
  2. 按以下顺序逐项压（从收益大、代价小开始）：
    1. 关 Lumen，改用烘焙静态光照 + SSAO/DFAO（本路线既定策略）
    2. 降 r.ScreenPercentage 到 60–70，TSR 保持 High
    3. 精度档位：把「验收档」的可见构件数控制在面片 ≤200 万
    4. VSM 压阴影 LOD bias；确认场景里没有滥用移动光源（缓存失效是主要开销）
    5. Nanite 确认已启用；检查是否存在被禁用 Nanite 的构件
  3. 做「验收档」一键切换：一个按键/按钮切到「面片 ≤200 万 + 稳定 ≥30 fps」的配置。
  4. 出证据：截图 stat fps + stat rhi（含面片数）→ 存 Docs\evidence\W04\；同时录一段「旋转/缩放/平移」的操作视频，因为合同写的是这三种操作下的帧率。
  • 知道瓶颈在 Game / Draw / GPU 哪一项
  • 有「验收档」一键切换
  • 面片 ≤200 万时 ≥30 fps（有截图 + 录屏证据，含旋转/缩放/平移三种操作）

D5（3 h）首次加载时间 ≤30 s

  1. 测打包后的首次加载时间（不是编辑器里！编辑器加载慢不代表打包后慢）。用秒表 + 录屏。
  2. 若超标，按以下顺序优化：
    • 确认 DDC（衍生数据缓存）已预热，着色器已编译
    • 加加载屏（Loading Screen）——用户感知的等待时间比实际时间重要，这也是演示体验的一部分
    • 检查是否有超大贴图；关掉不必要的高清资源
    • 模型精度档位：默认加载「标准档」而非「精细档」
  3. 出证据：从双击到画面可交互的录屏（含秒表或屏幕时间）。
  • 打包后首次加载 ≤30 s（有录屏证据）
  • 有加载进度提示

D6（3 h）第一次 27 条普查 + 月检

  1. 打开验收自测表，逐条过一遍 27 条，标记：已达标 / 部分 / 未开始。
    本周结束时，第 2、3、4、5、7、8 条应基本达标。
  2. 为每条已达标的条款补一个证据文件，按命名规范 C{条款号}_{类别}_{说明}.{ext} 存入 Docs\evidence\27条验收\。
  3. 把健康度写进 devlog：27 条中已达标 ___ 条。这个数字决定了后面 8 周的资源分配。
  4. 做月度复盘：哪一周实际耗时超了预估？原因是什么？把结论用于调整 W5–W8 的计划。
  • 27 条自查表已更新
  • 已达标条款均有证据文件
  • devlog 有「已达标 __ 条」的明确数字
