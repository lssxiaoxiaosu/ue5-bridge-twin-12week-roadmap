环境与管线：把三条链路打通

本周目标：打通「模型进 UE5 + 能打包 + 像素流基础设施就位」三条链路。不写任何业务逻辑。

建议工时 22–26 h 学习 : 实做 ≈ 35 : 65 对应合同条款 第 5、7、8 条（首次加载 ≤30 s、BIM 加载、格式支持）
开始之前：两个必须纠正的既有认知 ① 不要用 UE 5.3。你机器上装的是 5.3.2（2023 年），当前官方最新为 5.8。 注意：官方从未明文声明「5.3 不支持 RTX 50 系」，别把这句话写进方案。真实情况是——RTX 50 系的核心坑在驱动： 576.xx 驱动会因引擎内置的 RunHardwareBenchmark 触发启动崩溃，576.80 修复。你的驱动是 591.86，已达标，不需要动。 升级引擎的真实理由是：5.3 捆绑的 DLSS/Streamline/CUDA 依赖早于 Blackwell、版本落后 5 个大版本、Epic 已公布 UE6 路线图。
② 本机没有 Autodesk Revit。Datasmith Exporter 是 Revit 插件——即便你拿到 .rvt 也无法导出。 这一条是本周乃至整个项目的第一个硬障碍，D0 就要定方案。

Datasmith：本周的技术核心

在虚幻引擎中将 Datasmith 与 Revit 结合使用
Epic 官方已实测·中文正文必学（本周最重要）
→ 打开（中文）
为什么这周看：这是你整条模型管线的中文权威依据。必读要点：
① Revit 侧需单独安装 Datasmith 导出器插件，且导出器版本必须与 UE 版本匹配（不匹配会直接导入失败）；
② 必须先选中一个 3D 视图才能导出，该视图的可见性设置决定导出内容（可用剖面框 Section Box 只导局部——本周练手就靠它）；
③ Revit 元素实例属性会作为元数据挂到构件上，并写入 Component Tags（如 Revit.Instance.Id）；
④ Revit 的类别会转成 UE 的 Layer，可用于分层显隐；
⑤ 族参数与约束不会带进 UE（导入后是死几何）；
⑥ 曲面细分等级（Tessellation）默认 Level 8，是控制面片数的官方旋钮。

使用 Datasmith 元数据
Epic 官方已实测·中文正文必学（提前看）
→ 打开（中文）
为什么这周看：这是「构件级拾取看属性」这条验收硬条款的技术基础，本周先知道结论、W2 再动手。
关键结论（官方原文口径）：Get Datasmith User Data Value for Key 等节点属于 Datasmith User Data 类别， 「对性能影响极小，可随时使用，即使在项目运行时」，官方还给出了「运行时鼠标选中构件 → UMG 弹属性面板」的示例；

逐日任务（D0–D6）

D0（30–45 min，今天就能做）定版本 + 定 Revit 方案

这一步不做，后面全是赌博。

  1. 打开 Epic Games Launcher → 虚幻引擎 → 库 → 点 +，看能看到哪些版本：
    • 有 5.8 → 用 5.8（最新，对 RTX 50 系支持最完整）
    • 最新只有 5.6 / 5.6.1 → 用 5.6.1（Pixel Streaming 中文文档对应版本）
    • 不要用 5.3
    记下：UE 5.____
  2. 确认显卡驱动：你已是 591.86（RTX 50 系在 UE 上的已知坑是 576.xx 驱动崩溃，576.80 已修复）→ 不需要动驱动。
  3. 查清平南三桥 BIM 的三件事（问 BIM 提供方 / 项目负责人）：
    • 格式：.rvt 原生文件，还是只有 IFC？
    • 文件多大？
    • 谁负责导出？本机没有 Revit，三条路选一条：
      路 A（推荐）：找一台装了 Revit 的机器装 Datasmith 导出器，导出后把产物拷给你
      路 B：本机装 Revit（教育授权可申请；试用期仅 30 天，不建议在项目中途才开始用）
      路 C（兜底）：只拿 IFC，走 IFC 导入流程（属性与几何质量通常不如 rvt 路线）
  • 写下了确定的 UE 版本号
  • 写下了 BIM 格式与文件大小
  • 写下了导出方案（A/B/C）与责任人姓名、约定交付日期
卡住时查什么 「SM_120 / Blackwell UE 崩溃」→ 关键词 RTX 50 series UE crash 576.80；版本差异 → 官方 Release Notes（URL 加 ?application_version= 可切版本）

D1（2–3 h）装引擎 + 目录与规范落地

  1. 装 UE（约 1–2 h 下载，后台跑）。安装路径不要放 C 盘；可选组件只勾 Windows 目标平台。
  2. 建目录骨架： 
    D:\UE\
├─ BridgeTwin\      ← UE 工程（纯 ASCII，绝不带中文/空格）
├─ Model\           ← 原始 BIM 与导出产物（Revit / ifc / udatasmith）
├─ PixelStreaming\  ← 像素流基础设施（git clone 目标）
├─ Build\           ← 打包产物
└─ Docs\            ← 文档与证据（验收要交）
    为什么强调纯英文路径 你现有工作区路径含中文（DeepSeek Harness、01_xidagongqiao_demo），UE 工程绝不能放那里，否则会出现难以定位的编译/打包失败。
  3. 配置 git 身份（当前未配置，不配后面提交会失败）： 
    git config --global user.name  "你的名字"
git config --global user.email "你的邮箱"
  4. 在 D:\UE\Docs\ 建 devlog.md，每天写 3 行：今天做了什么 / 卡在哪 / 明天第一件事。
  • UE 装完，能从 Launcher 启动并新建工程
  • D:\UE\ 五个子目录已建齐
  • git config --global user.name 能输出你的名字

D2（3–4 h）第一次 Datasmith 导入（只导一小块，不要导全桥）

目的：把管线走通一次。全桥是 D4 的事。

  1. 拿到导出产物（按 D0 定的路 A/B/C）。路 A/B 请先建一个只显示局部（例如单侧一段拱肋）的 3D 视图再导出，用小模型练手。
  2. 新建工程：Games → Blank，命名 BridgeTwin，位置 D:\UE\BridgeTwin，不勾 Starter Content，C++ 选项选 Blueprint。
  3. 启用插件：Edit → Plugins → 搜 Datasmith → 启用 Datasmith Importer → 重启编辑器。
  4. 导入：工具栏 Datasmith → Import，导入选项先全默认。
  5. 读数据（本周最有价值的 30 分钟）：World Outliner 看层级是否按 Revit 楼层/族组织；选中构件 → Details 面板找 Datasmith User Data，看能否看到编号、族、类型、材质。把所有可用的 key 名抄下来——W2 的分类全靠它。
  6. 量两个数（写进 devlog）：控制台（` 键）输入 stat fps 与 stat rhi，记录面片数与 fps；记录导入耗时。
  • 模型出现在关卡里，能自由查看
  • 选中构件能看到 Datasmith 元数据
  • 记录：面片数 = ______，fps = ______，导入耗时 = ______
  • Output Log 零红色报错
卡住时查什么 「Datasmith 菜单找不到」→ 插件没启用或没重启　｜　「一片黑/没材质」→ 查 RevitMaster 材质　｜ 「缺构件」→ 回 Revit 检查那个 3D 视图的可见性与剖面框　｜　「IFC 丢属性」→ Datasmith IFC importer metadata

D3（3–4 h）把导入这件事「做熟」：定工艺参数

  1. 搞懂曲面细分等级（Tessellation）：在 Revit 的 Datasmith 导出设置里（默认 Level 8）。导出两版对比：Level 8 与 Level 3–4，分别导入比较面片数与外观差异。
    结论写进 devlog：可接受的最低细分等级 = ___，对应面片数 = ___
  2. 搞懂构件分类靠什么字段：看命名规律（Revit 族名/类型名会带进命名）与元数据。目标是把构件归到 8 类：主拱肋（两侧各 22 节段含合龙段）/ 32 对吊杆 / 横联钢管 / 腹杆 / 桥面系钢格子梁 / 两端塔架 / 缆索 / 基础。先别写蓝图，先用眼睛确认靠什么能区分。
  3. 学会打包（今天至少试一次，哪怕空关卡）：Platforms → Windows → Package Project，输出到 D:\UE\Build\，完成后双击 exe 能独立运行。
    ⚠️ 第一次打包会编译着色器，可能 30–60 min，后台跑着，你继续做别的。
  • 拿到「细分等级 ↔ 面片数」对照表（≥2 组数据）
  • 能说出 8 类构件各自的识别字段
  • 打包产物能独立运行

D4（4–5 h）全桥导入 + 面片预算（本周核心）

  1. 全桥导出与导入（用 D3 定的细分等级）。建议先做一次中等规模测试（整片拱肋 + 桥面系），再上全桥。
  2. 面片预算核算（合同硬指标：面片 ≤200 万时帧率 ≥30 fps）。用 stat fps / stat rhi 记录。若远超 200 万，按以下顺序压：
    1. 降 Tessellation 等级（第一手段）
    2. 开启 Nanite（模型右键 → Nanite → Enable）。注意：Nanite 不支持 Instanced Static Mesh，且会增加显存占用
    3. UE 的 Proxy Geometry 工具减面（官方推荐用于 Datasmith 的三角化结果）
  3. 建立「精度档位」概念（精细 / 标准 / 流畅）：先用关卡可见性与图层实现三档显隐，不写复杂逻辑。
  4. 第一次性能基线测量（要留证据，第三方测试报告会要）：截图 stat fps + stat rhi，存到 D:\UE\Docs\evidence\W01\。
  • 全桥在 UE 里可自由查看
  • 有「面片数 ↔ fps」实测数据，且知道怎么压到 200 万以内
  • Docs\evidence\W01\ 里有性能截图
卡住时查什么 「帧率个位数」→ stat gpu 找最贵的那一项（通常是 Lumen / 虚拟阴影 / TSR）　｜　「开 Nanite 反而慢」→ 看是否 GPU 受限、显存是否吃满　｜ 「导入卡死」→ 缩小范围分批导入

D5（2–3 h）像素流基础设施就位（只验证「能启动」）

先记住一个已核实的限制 PS2 里「一个 UE 实例 = 一份渲染 = 所有浏览器同一视角」。所以 2–4 人同时看是天然支持的；但「每人独立漫游」需要一实例一流。 今天的任务不涉及这个决定。
  1. 克隆像素流基础设施（Node 与 npm 你机器上已具备）： 
    cd D:\UE\PixelStreaming
git clone --branch UE5.8 https://github.com/EpicGamesExt/PixelStreamingInfrastructure.git
    分支号要与你选的引擎版本对应。实测分支现状：UE5.8 = Current、UE5.7 = Supported、UE5.6 = EOL、master = Dev。不确定就先 git branch -r 看有哪些分支。
  2. 安装并启动信令服务器： 
    cd D:\UE\PixelStreaming\PixelStreamingInfrastructure\SignallingWebServer\platform_scripts\cmd
.\setup.bat          # 装依赖，可能几分钟
.\start.bat          # 启动
    默认端口：streamer 8888 / player 80 / sfu 8889。
  3. 引擎侧连一次：UE 工程启用 Pixel Streaming 插件 → 重启 → Standalone Game 启动（Editor Preferences → Level Editor → Play → Additional Launch Parameters 填 -PixelStreamingURL=ws://127.0.0.1:8888）。信令服务器出现 Streamer connected ＝ 成功。
  4. 浏览器接入：打开 http://127.0.0.1，点页面 → 点播放，能看到引擎画面 ＝ 本周最大风险项解除。
  • start.bat 能启动，日志显示 8888 / 80 监听
  • 信令服务器出现 Streamer connected
  • 浏览器能看到 UE 画面并操作
卡住时查什么 「80 端口被占用」→ 关掉其他 Web 服务，或改 config.json 的 player_port　｜　 「setup.bat 报错缺编译工具」→ 装 Visual Studio Build Tools（C++ 桌面开发），这是唯一可能需要 VS 的场景　｜　 「连上但黑屏」→ 关键词 Pixel Streaming black screen firewall、确认走 GPU 编码　｜　 「别的电脑看不到」→ Windows 防火墙放行 80/8888，用局域网 IP 而非 127.0.0.1
