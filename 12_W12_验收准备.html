WEEK 12 ／ 12

验收准备：让 27 条在现场一条都不掉链子

本周目标：按合同 27 条逐条现场演练；第三方测试用例与证据包定稿；演示脚本与应急预案就绪；文档终版。

建议工时 22–26 h 学习 : 实做 ≈ 10 : 90 对应 合同验收条款 本周性质 不学新东西，只做收敛
先把验收条款再读一遍（它决定本周怎么做事） 「货物验收时由采购人对照采购文件的《技术参数及性能（配置）要求》进行全面核对检验， 对所有要求出具的文件和材料的原件进行核查，如不符合采购文件要求或提供虚假承诺的、虚假检测报告等任何虚假材料的， 采购人有权拒绝验收并认定成交供应商违约。」
另外：「采购人需负责安装、调试（测试），并完成采购人的使用操作培训」——培训也是验收条件之一，别忘了准备。
📚 本周参考资料（点开／收起）
本周不需要任何技术教程 你已经拥有全部技术。本周唯一要看的文档是你自己前面 11 周攒下的东西： devlog、验收自测表、证据包、W7 的全链路验证用例、W9 的故障速查表。

逐日任务（D1–D6）

D1（4 h）第一遍现场演练：按合同顺序逐条过

  1. 按合同条款顺序（1→27）演练，不要按你的演示习惯顺序。因为验收人是拿着合同逐条核对的。
  2. 每一条演练时做三件事：
    • 实际操作一遍（不是口头说「这个有」）
    • 调出对应证据文件
    • 在自测表上记录：通过 / 有问题 / 缺证据
  3. 重点排练这 5 条 ▲ 硬指标（它们最受关注）：
    条款演练要点
    ▲1孪生场景可运行 + 含监测数据联动（要能说清与实体模型/吊装系统的一致性口径）
    ▲7BIM 加载与轻量化解析流程演示 + 拱肋应力、位移两类状态着色（注意：合同点名了这两类）
    ▲11实时监测概览页 + 应变/位移/温湿度/风速动态展示 + 理论值对比 + 数据导出图表
    ▲16传感器类型/协议/设备管理 + 预处理 + 多维统计 + 自定义阈值 + 报警与模型位置关联
    ▲22菜单/组织/权限/用户/日志五个模块都要能打开
  4. 记录所有「卡顿、等待、要翻找」的环节——这些在验收现场会变成尴尬的空白时间。
  • 27 条全部实际操作过一遍
  • 5 条 ▲ 已重点排练
  • 问题清单已列出

D2（3–4 h）修补：把问题清单清零

  1. 按优先级修问题：
    1. 功能缺失（会导致拒收）——最高优先
    2. 证据缺失（能被质疑）——次高
    3. 体验问题（等待、卡顿、要翻找）——能修就修
  2. 对修不完的，做两件事：
    • 准备替代演示路径（例如：渲染卡顿时改用截图讲，或换演示档）
    • 准备诚恳的解释话术——「这一项当前实现到什么程度」比硬撑更可信
  3. 不要在本周引入新功能：新功能 = 新风险，此时任何未经演练的功能都可能当场翻车。
  • 功能缺失项已清零（或已有书面处置）
  • 证据缺失项已补齐
  • 没有引入新功能

D3（4 h）第二遍演练：模拟真实验收场景

  1. 换个身份演练：找一位不了解项目的同事（或你自己扮演「挑剔的甲方」）， 让他拿着合同 27 条随机抽查，而不是按你的顺序。
    • 这一步的价值极高——你会发现自己「以为讲清楚了」但别人听不懂的地方
  2. 演练三个关键场景（超时、断网、误操作）：
    • 如果设备掉线了怎么办 → 切到仿真数据源（W3 已准备）
    • 如果像素流连不上怎么办 → 直接双击打包 exe 演示（W9 已准备）
    • 如果有人说错了数 → 知道去哪调出原始证据
  3. 时间控制：完整演示一遍，记录用时。验收通常有时间限制，要能压缩到 20–30 分钟。
  4. 再录一遍演示视频作为终版。
  • 被别人随机抽查过一遍
  • 三个应急场景都演练过
  • 完整演示可在 30 分钟内完成

D4（3–4 h）第三方测试配套 + 培训材料

  1. 测试用例定稿（若 W11 未完成则今天必须完成）：
    • 按 27 条逐条：条款号 → 测试目的 → 前置条件 → 操作步骤 → 预期结果 → 证据形式
    • 性能类指标写清测试方法（分辨率、画质档、工具、采样次数、取最大值还是平均值）
  2. 确认第三方测试排期（若合同要求验收前提供报告，这一步可能已经在跑；若还没启动，今天必须启动——机构排期不可控）。
    • 问清：需要我方提供什么（用例、环境、数据、账号）？
    • 问清：测试在现场做还是送测？需要多长时间出报告？
  3. 准备培训材料（合同要求「完成采购人的使用操作培训」）：
    • 一页速查卡（怎么打开、怎么操作三维、怎么看告警）
    • 操作手册作为培训讲义
    • 录一段 10 分钟的操作视频（培训时可反复看，也省你重复讲）
  • 测试用例定稿（覆盖 27 条）
  • 第三方测试排期已确认
  • 培训材料就绪（速查卡 + 讲义 + 视频）

D5（3 h）文档终版 + 代码/工程整理（若需交付源码）

  1. 三类文档定稿：操作手册、部署文档、测试用例。检查：
    • 版本号与日期
    • 截图是否为最新界面
    • 软件版本号是否与实际部署一致（引擎、Node、数据库、EMQX）
  2. 若需交付源码/工程（你已确认按「要交」准备）：
    • 整理工程目录：删除临时资产、测试关卡、无用插件
    • 蓝图命名与注释检查（现在补注释还来得及，但不要大改命名——改命名会引入 bug）
    • 写一份 README.md：工程结构、依赖插件清单、如何打开与打包、关键蓝图在哪个目录
    • 把「必须的第三方依赖」列出来（引擎版本、插件、Node 模块、数据库扩展）
  3. 整理交付目录，让验收人一眼能找到东西： 
    交付\
├─ 01_平台软件\          ← 打包程序 / 源码工程 / 部署包
├─ 02_操作手册.pdf
├─ 03_部署文档.pdf
├─ 04_测试用例.docx
├─ 05_第三方测试报告.pdf   ← 若已取得
├─ 06_验收自测表与证据索引.xlsx
└─ 07_培训材料\          ← 速查卡 + 操作视频
  • 三类文档定稿且版本一致
  • 工程整理完成，有 README
  • 交付目录结构清晰

D6（3 h）验收当天检查清单 + 心态准备

  1. 做一份「验收当天检查清单」（打印出来，当天照着做）：
    • 设备：演示机、投影/大屏线材、第二台观看设备、网络（是否需热点备用）
    • 软件：一键启动脚本、打包 exe（保底）、浏览器（Chrome/Firefox）、已登录的测试账号
    • 数据：传感器是否通电、Broker 是否正常、仿真数据源是否可切
    • 资料：交付目录、打印版操作手册、证据索引打印版
    • 提前 1 小时：冷启动一遍，确认全部就绪
  2. 准备三个版本的讲解深度：
    • 2 分钟版：一句话说清平台做什么 + 演示三维联动
    • 10 分钟版：覆盖 27 条主要功能
    • 30 分钟版：逐条对照，含证据调取
  3. 心态准备：被问到答不上来的问题，正确回应是「这一点我记下来，稍后书面回复」， 不要当场猜测或编造——验收条款明确写了「提供虚假承诺」会导致拒收。
  4. 最后一遍确认 27 条：每条都能实际操作 + 能调出证据。
  • 验收当天检查清单已打印
  • 三个深度的讲解都演练过
  • 27 条最终确认：可操作 + 有证据

12 周路线的最后一句提醒 这个项目的验收不看「你做了多少」，只看「合同 27 条是否逐条满足且能证明」。 所以最后一周最重要的工作不是写代码，而是把已经做成的事变成可查验的证据。 把这件事做扎实，前面 11 周的努力才真正兑现。
回看与复盘 验收结束后，花半天做一次复盘并写进 devlog：哪一周的预估偏差最大？哪个技术判断错了？ 哪些坑是可以提前避免的？这份复盘是你下一项目最值钱的资产（也是本路线文档可以迭代的依据）。
