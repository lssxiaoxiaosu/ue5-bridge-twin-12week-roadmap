联动闭环：看板、对比分析与全链路验证

本周目标：把合同第 11–14 条的看板做全（≥7 类指标、理论/实测同轴对比、三项误差统计），并完成一次全链路闭环验证——从真实传感器到浏览器看板与三维着色同时正确。

建议工时 22–26 h 学习 : 实做 ≈ 30 : 70 对应条款 第 11、12、13、14 条 里程碑 数据联动闭环
本周是本项目「看起来成了」的一周 前面六周你都在打地基。本周结束时，屏幕上会同时出现：三维构件随真实数据变色 + 浏览器里曲线在动 + 告警在跳。 这就是验收现场最主要的画面。把这一周的成果录成一段 5 分钟的视频，它会是后续所有汇报的基础素材。

  2. 每类指标至少要有：实时数值卡片 + 实时曲线 + 历史曲线入口。

  • 刷新周期可配且默认 ≤5 s，界面可见

D2（3–4 h）理论值 vs 实测值对比 + 三项误差统计

  1. 理论值从哪来？这是本条的关键前提，必须先想清楚：
    • 方案 A：有限元计算/设计值（由第 1、3 项的相关方提供）
    • 方案 B：设计公式估算（如索力理论值、挠度理论值）
    • 方案 C：试验工况的理论预期值（加载配重与预期应变/位移）
    无论用哪种，都要在文档里写明来源与假设——验收时甲方一定会问「你的理论值怎么来的」。
  2. 做同轴对比曲线：理论值与实测值画在同一套坐标轴上（不要双 Y 轴）。
  3. 做三项误差统计：
    • 绝对误差 = |实测 − 理论|
    • 相对误差 = |实测 − 理论| / |理论| × 100%
    • 相关系数 = 两组序列的皮尔逊相关系数
    每项都要显示数值，并说明统计区间（哪个时间段、多少个样本）。
  • 理论值来源已明确并成文
  • 同轴对比曲线可交互
  • 三项误差统计有数值、有区间说明

D3（3–4 h）四种展示形式同步（合同第 13 条）

  1. 实时数值面板：关键指标的当前值、单位、状态色。
  2. 实时/历史曲线：切换时间范围（1 h / 24 h / 7 d 等）。
  3. 三维模型着色联动：这是本周的技术重点——
    • Web 看板选中一个测点 → 通过 MQTT 主题发指令 → UE5 高亮对应构件并显示其值
    • UE5 里点选构件 → 回推给 Web → 看板切换到该测点的曲线
    • 双向都要通，否则演示时不顺手
  4. 统计报表：把 W6 的报表面板挂进看板入口。
  • 四种展示形式在同一个界面里协同工作
  • Web ↔ UE5 双向联动可用（各录一段）

D4（4 h）全链路闭环验证（里程碑判定）

这是本周最重要的半天，必须一次做完并录屏 全链路 = 真实传感器 → 采集箱 → Broker → 库 → Web 看板 + UE5 三维，中间不能有任何一段是手工造的假数据。
  1. 设计一个可复现的验证流程（写下来，作为第三方测试用例的雏形）：
    1. 记录起始时间
    2. 对某个测点施加一个可观测的变化（加载配重、或让设备产生明显变化）
    3. 观察：库里出现数据 → Web 看板数值变化 → UE5 对应构件颜色变化 → 若越限则告警产生
    4. 记录全过程的端到端时间
  2. 做 ≥3 轮，每轮都记录延迟；取最大值作为指标值。
  3. 录屏 + 保存时间戳日志，存入 Docs\evidence\W07\。
  4. 把流程写成《全链路验证用例》文档——W12 的第三方测试报告直接从这里改。
  • 全链路一次跑通（无手工造假环节）
  • ≥3 轮验证，延迟最大值 ≤2 s
  • 流程已写成用例文档
  • 录屏与日志已归档

D5（3 h）看板体验与边界处理

  1. 演示友好性：大屏/投影分辨率适配；字号够大；配色在投影下能看清（深色底 + 高饱和强调色通常更好）。
  2. 边界情况：
    • 无数据时显示「无数据」而不是空白或 0（0 会被误读为真实值）
    • 数据中断时显示最后更新时间 + 断开提示
    • 超量程数据显示为「超量程」并标注
  3. 数据来源标识：按你原型的做法，界面上固定显示「演示数据 / 真实数据」标识——这是诚实也是保护自己。
  • 投影下可读
  • 无数据/断线/超量程都有明确提示
  • 数据来源标识可见
